# ADR 0007: Installable app that reads offline

- Status: Accepted
- Date: 2026-10-15

## Context

Most students use Trackit on their phones, often with poor or no signal
(lecture halls, transport, mobile data running out). They should be able to
install it to the home screen and still see their tasks and exams without a
connection. Phones are also shared, so one student's data must never be
shown to the next person who opens the app.

## Decision

### Service worker and manifest

- Use `vite-plugin-pwa` in `generateSW` mode (Workbox), configured in
  `frontend/vite.config.js` (`pwaOptions`).
- The manifest gives the name, `short_name`, `display: standalone`,
  `start_url` and `scope` of `/`, the existing `theme-color` (`#0F172A`) and
  the light theme's background (`#F8FAFC`), and 64, 192 and 512 pixel icons
  plus a 512 pixel maskable icon. The icons are the clock emblem from
  `logo.png` (the wordmark is unreadable at icon size), generated by
  `scripts/generate-pwa-icons.py` and committed; the maskable icon keeps the
  emblem inside the central 80% safe zone.
- The service worker precaches only the built app shell: HTML, JavaScript,
  CSS, fonts and the images the app shows. Install icons and the social
  preview image are left out, because the browser fetches install icons
  itself.
- It has **no runtime caching**. Requests it does not precache, including
  every `/api` call, `/api/chat/stream` and all Supabase Auth, REST and
  Realtime traffic, go straight to the network as if there were no service
  worker. API responses are never written to Cache Storage, where they
  would be shared by every user of the browser and survive sign-out.
- Navigations to unknown paths get the cached `index.html`, so deep links
  open offline, except `/api` and `/api/*` (`navigateFallbackDenylist`),
  which must reach the API or fail rather than receive the SPA.
- Updates wait for the user (`registerType: 'prompt'`, no `skipWaiting` or
  `clientsClaim`). When a new version is waiting, `UpdatePrompt.jsx` offers
  "Reload" or "Later". Swapping code under an open page could mix chunk
  versions or lose a half-written task.

### Signed-in data offline

- React Query's cache is persisted to IndexedDB with
  `@tanstack/react-query-persist-client` and an async storage persister over
  `idb-keyval` (`src/lib/queryPersistence.js`, `UserQueryCache.jsx`).
- Each user's cache is stored under `user:<id>` and only restored for that
  user. Saved data older than seven days is discarded, as is everything
  when `CACHE_VERSION` is bumped.
- On sign-out, `AuthContext.signOut` empties the in-memory cache and
  deletes every saved cache before calling Supabase, so the data is gone
  even if the sign-out request fails offline. `UserQueryCache` does the same
  whenever the signed-in user changes or disappears (another tab, an expired
  refresh token). A persister write still pending from the previous user is
  dropped rather than saved after the clear.
- A user who closes the app without signing out leaves their cache behind.
  It is deleted the next time the app opens with nobody signed in, and
  before any other user's cache is restored, so it never stays on the
  device once someone else uses the app.
- The app waits (a few milliseconds, at most two seconds) for the saved
  cache to be restored before rendering signed-in pages, so they start from
  it rather than an empty list.
- Offline, supabase-js cannot refresh an expired access token. It keeps the
  session but retries for up to 30 seconds and then reports none, which
  would send the user to the landing page. When the app starts offline,
  `AuthContext` uses the saved session's user straight away so they can
  read their saved data; supabase-js refreshes the token once the device is
  back online. Nothing can be sent with the expired token, because writes
  are disabled offline.

### Offline behaviour

- Online status comes from React Query's `onlineManager`, set from
  `navigator.onLine` at startup (React Query otherwise assumes it starts
  online). Queries pause offline and show saved data; the banner, disabled
  controls and paused queries all use this one source.
- `OfflineBanner` says the app is offline and showing saved data. Adding,
  editing, deleting, completing tasks, chat and uploads are disabled, with
  the reason next to the main controls. As a backstop, `apiRequest` refuses
  any non-GET request offline with the same message, and mutations fail at
  once (`networkMode: 'always'`) instead of being queued silently.

### Headers

- `sw.js` is served with `Cache-Control: no-cache`, so browsers check for a
  new version on every visit; the manifest is served as
  `application/manifest+json`. Both are set in `vercel.json` and
  `frontend/nginx.conf`, where a missing `sw.js` is a 404 rather than the
  SPA shell.

### Content-Security-Policy

No change to the policy from ADR 0005 was needed:

- The service worker is registered from the bundled JavaScript
  (`injectRegister: false`), so there is no inline script.
- `manifest-src` and `worker-src` are not set, so they fall back to
  `default-src 'self'`, which allows the same-origin `manifest.webmanifest`
  and `sw.js`. The service worker loads its Workbox runtime from the same
  origin.
- The `<meta>` policy governs the page, not the worker. The worker's own
  requests are the same-origin precache downloads.

The end-to-end suite runs the production build with the policy and fails on
any violation.

## Consequences

- The first visit must be online; the app works offline from the second
  load, once the service worker is installed.
- Offline pages show data as of the user's last online visit to them, up to
  seven days old. Pages never opened online have nothing to show offline.
- Saved data sits unencrypted in the browser's IndexedDB until sign-out (or
  until the app next opens for someone else or for nobody), like any browser
  cache. Users of shared devices must sign out. iOS Safari may
  evict it after a few weeks without use.
- If the sign-out request fails offline, the cached data is deleted but the
  Supabase session stays on the device until the user signs out again
  online.
- Each deploy shows the update prompt to open tabs. A change to the shape
  of API data that old caches would break needs a `CACHE_VERSION` bump.
- To regenerate the icons after changing `logo.png`:
  `python3 scripts/generate-pwa-icons.py`.
