# Timetable parser evaluation

Measures how accurately `lib/timetableParser.js` turns exam timetables and
weekly class schedules into structured records.

## Running it

```bash
cd backend
npm run eval                                   # uses ANTHROPIC_API_KEY and ANTHROPIC_MODEL
npm run eval -- --model claude-sonnet-4-5      # compare another model
npm run eval -- --only french                  # run a subset by case id
npm run eval -- --oracle                       # offline self-check (must score 100%)
```

Each run writes a JSON report and a Markdown summary to `eval/results/`
(git-ignored). The JSON records the model, temperature, dataset version and
seed, git commit, token usage, per-case scores, and every field-level error,
so any run can be reproduced and compared. A full run is 20 API calls.

The oracle mode feeds the ground truth back in as predictions. CI runs it on
every push to prove the dataset, loader and scorer are consistent.

## Dataset (`dataset/v1`)

20 synthetic documents with 145 ground-truth records, generated by
`generate-dataset.js` from a fixed seed (`node eval/generate-dataset.js`
reproduces the manifest exactly).

| Dimension     | Variants                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| Document type | 14 exam timetables, 6 weekly class schedules                                                            |
| Layout        | table, bulleted list, grouped by date; schedule grid, schedule by day                                   |
| Date format   | ISO `2026-12-07`, `07/12/2026`, `Monday 7 December 2026`, `07-Dec-2026`, French `lundi 7 décembre 2026` |
| Time format   | `13:00`, `1:00 PM`, French `13h` / `13h30`                                                              |
| Language      | English, French                                                                                         |
| Rendering     | 12 text PDFs, 8 rasterised PNG images (tests vision rather than embedded text)                          |
| Missing data  | venues shown as `TBA` or omitted; course codes omitted                                                  |
| Distractors   | headers, institution names, exam-room rules in the footer                                               |

Datasets are versioned: never edit `v1` in place. Add `v2` with a new seed
or new cases so results stay comparable over time.

## Metrics

**Exams.** Predicted exams are matched one-to-one to expected exams by
subject similarity (token Jaccard ≥ 0.6, or an identical course code).

- _Precision / recall / F1_: micro-averaged over all records. Recall drops for
  missed exams; precision drops for invented ones.
- _Field accuracy_: on matched records, the share with the correct date, time,
  course code and venue, after normalising case, accents, punctuation and
  time format (`9:00 AM` = `09:00`, `13h30` = `13:30`).
- _Exact records_: share of expected exams where every field is correct. This
  is the strictest figure and the one that best predicts whether a student
  can import without editing.

**Schedules.** A predicted class session is correct when its day, start
time, end time and subject match an expected session.

Results are also broken down by slice (layout, date format, language,
image vs PDF) to locate failure modes.

## Limitations

- The documents are clean and synthetic. Real timetables (scans, photos at
  an angle, merged cells, multi-page PDFs) will be harder, so treat these
  numbers as an upper bound. Adding a small set of anonymised real
  timetables as `v2` is the most valuable next step.
- Ground truth for missing venues is `null`; a parser returning `"TBA"`
  counts as a venue error.
- Years are always present in the documents, so year inference is untested.
